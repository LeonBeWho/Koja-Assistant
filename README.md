# Koja Core

Koja Core is a local Jarvis-inspired voice assistant with a neon Tkinter HUD. It listens through your microphone, speaks through Piper TTS, asks OpenClaw for the full tool-enabled Koja brain, and can fall back to a local Ollama/LlamaIndex setup. Spotify controls are optional.

## Features

- Tkinter desktop HUD (`koja_app.py`) plus a CLI/core voice loop (`koja-core.py`)
- Voice input via `SpeechRecognition` / `PyAudio`
- Spoken replies via local Piper TTS with cross-platform playback helpers
- OpenClaw bridge using session `koja-voice`
- Local Ollama/LlamaIndex fallback context engine
- Optional Spotify Web API controls: play, pause, resume, next, previous, status, and search/play track
- OS-aware helpers for Linux, macOS, and Windows terminal/browser/screenshot/audio playback

## Repository layout

```text
koja_app.py          # Tkinter HUD app; recommended entry point
koja-core.py         # voice assistant core used by the HUD
koja_app.spec        # PyInstaller one-folder build spec
build_app.sh         # convenience build script
requirements.txt     # Python runtime + build dependencies
.env.example         # optional Spotify config template
data.example/        # safe example context folder
```

Large runtime assets are intentionally not tracked by Git:

```text
piper/               # Piper executable and shared libraries
models/              # Piper voice model files, e.g. *.onnx and *.onnx.json
data/                # optional private local retrieval/context notes
.env                 # optional local secrets/config
.spotify-token-cache # generated by Spotify login
```

## Requirements

- Python 3.10+
- Tkinter for your Python install
- A working microphone/audio stack
- Piper binary and a compatible Piper voice model
- Optional: OpenClaw CLI for the full Koja brain
- Optional: Ollama if you want the local fallback brain
- Optional: Spotify developer app credentials for Spotify commands

On Linux, `PyAudio` and `tkinter` may require system packages before `pip install` succeeds. Package names vary by distro; examples include `python3-tkinter`, `portaudio-devel`, `python3-devel`, or their equivalents.

## Setup from a fresh clone

```bash
git clone <your-repo-url> koja-core
cd koja-core
python -m venv .venv
source .venv/bin/activate
python -m pip install --upgrade pip
python -m pip install -r requirements.txt
```

### Add Piper assets

Koja expects these paths relative to the project folder when running from source:

```text
./piper/piper                         # Linux/macOS
./piper/piper.exe                     # Windows
./models/en_US-hfc_male-medium.onnx
./models/en_US-hfc_male-medium.onnx.json
```

Download/provide the Piper binary for your operating system and the voice model separately.
On Linux/macOS, ensure the Piper binary is executable:

```bash
chmod +x ./piper/piper
```

You can override the defaults if your assets live elsewhere:

```bash
export KOJA_PIPER_PATH="/path/to/piper"
export KOJA_MODEL_PATH="/path/to/voice.onnx"
```

### Optional local context

If you want local retrieval/context notes, copy the example folder and add your own files:

```bash
cp -r data.example data
```

Do not commit private notes in `data/`; it is ignored by Git.

### Optional OpenClaw

For the full Koja brain, install/configure OpenClaw and verify it works:

```bash
openclaw status
```

Koja calls:

```bash
openclaw agent --local --session-id koja-voice --json
```

If OpenClaw is unavailable, Koja will try the local Ollama/LlamaIndex fallback path.

### Optional Spotify API

Create a Spotify app at <https://developer.spotify.com/dashboard> and add this redirect URI:

```text
http://127.0.0.1:8888/callback
```

Then copy the example environment file and fill in your own values:

```bash
cp .env.example .env
```

Koja loads `.env` automatically when `python-dotenv` is installed. You can also export the variables manually:

```bash
export SPOTIPY_CLIENT_ID="your_client_id"
export SPOTIPY_CLIENT_SECRET="your_client_secret"
export SPOTIPY_REDIRECT_URI="http://127.0.0.1:8888/callback"
```

The first Spotify command opens a browser login. A local `.spotify-token-cache` file will be created and reused later.

## Run from source

Recommended HUD app:

```bash
source .venv/bin/activate
python koja_app.py
```

Core voice loop without the HUD:

```bash
source .venv/bin/activate
python koja-core.py
```

In the HUD, click **LOAD CORE**, then **START VOICE LOOP**, or type into **TEXT OVERRIDE** and press Ctrl+Enter.

Say `go to sleep`, `exit`, or `goodbye` to stop the voice loop.

## Build an executable

PyInstaller builds are OS-specific. Build on the OS you want to release for:

- Linux build: run PyInstaller on Linux → `KojaCore`
- Windows build: run PyInstaller on Windows → `KojaCore.exe`
- macOS build: run PyInstaller on macOS → macOS executable/app bundle style output

Install dependencies first, then on Linux/macOS run:

```bash
./build_app.sh
```

On Windows, use the same spec directly:

```powershell
python -m PyInstaller --clean --noconfirm koja_app.spec
```

The Linux/macOS PyInstaller one-folder output is created at:

```text
./dist/KojaCore/KojaCore
```

Run it with:

```bash
./dist/KojaCore/KojaCore
```

On Windows, run the generated `.exe` inside `dist\KojaCore\`.

### Runtime assets for the executable

The default build keeps Piper, voice models, private context, and `.env` outside the bundled app so the GitHub release stays smaller and safer. After building, place/copy OS-matching Piper assets beside the bundled Python files under `dist/KojaCore/_internal/`:

```bash
cp -r piper models dist/KojaCore/_internal/
# optional local config/context:
cp .env dist/KojaCore/_internal/        # if using Spotify .env config
cp -r data dist/KojaCore/_internal/     # if using local private context
```

For Windows releases, copy a Windows Piper binary as `piper/piper.exe`. For macOS/Linux releases, copy the matching `piper/piper` binary.

If you prefer a heavier self-contained build, edit `koja_app.spec` and add `piper/`, `models/`, and any safe non-secret data to `datas`. Do not bundle `.env`, Spotify token caches, or private `data/` files into public release artifacts.

## GitHub safety checklist

Before committing or publishing a release, check:

```bash
git status --short
```

Do not commit:

- `.env` or real Spotify credentials
- `.spotify-token-cache*`
- private `data/` notes
- local OpenClaw workspace files
- generated screenshots/audio files
- large Piper/model assets unless you intentionally want to host them

The included `.gitignore` is set up to exclude those by default.
